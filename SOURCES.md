## Each source in full

### `goldstandard.registry.projects`

**Gold Standard Foundation** (first party) · monthly · active

Every project in the Gold Standard carbon registry: name, status, methodology, type, size, estimated annual credits, crediting period, and a SustainCert id. 4,207 projects over 169 pages on 2026-09-22.
NOBODY ELSE HOLDS THIS, AND HERE IS THE EXACT NUMBER. The list endpoint public-api.goldstandard.org/projects has ZERO Internet Archive mementos. That sentence is narrow on purpose: the Archive DOES hold 35 individual project records under that host (144 captures, 2023-2026, all HTTP 200), so "zero mementos" is true of the list and false of the host. 35 of 4,207 is 0.8% of the register, which is why the claim survives being stated precisely rather than loosely -- re-measured 2026-09-23 once the Archive came back up.
registry.goldstandard.org/projects has 68 mementos spanning 2021-2026, and four sampled captures are ~2 KB client-rendered shells with 59 characters of visible text and not one project id in them. The UI is a JS app and the Archive photographed an empty frame 68 times. So the coverage check passes on measurement, not assumption.
THE PAGE COUNT IS NOT KNOWABLE AHEAD. The API is a bare JSON array, 25 per page, with no total in the response, so the capture is "page until an empty array" - 169 pages today and a different number next month. The engine takes a fixed endpoint list and deliberately has not grown a paging primitive for this: the registry is where what-will-be-fetched belongs, so `examples/refresh_endpoints.py` materialises the list in the workflow before `wss validate`, and the diff is the signal. wss-gho generates its 3,321 endpoints the same way.
THE SHRINK GATE IS ON THE REGISTER, NOT THE PAGE. The last page holds between 1 and 25 projects and oscillates every time the register grows, so a per-endpoint max_shrink_pct fires on it by design - and a quarantined page is never archived, so that gate would drop real data about once a month. refresh_endpoints.py asserts the whole register has not lost more than 40% of its projects and refuses to rewrite if it has; per page, must_contain still rejects an error or empty body.
PARSED BY parsers/gsproject_v1.py, keyed on sustaincert_id -- the identifier that appears in sustaincert_url and is therefore the one anything outside this registry can join on. `listed` is emitted once per project per capture and its ABSENCE later is the finding, since status carries no terminal value. `updated_at` is the registry's own edit stamp, present on all 4,207 projects with 3,460 distinct values, and is what makes a silent in-place edit datable. First parse of the baseline: 82,326 observations over 4,207 projects, 387,460,153 estimated credits a year in total.
TRAP IN THE DATA: created_at puts 1,774 of 4,207 projects in 2019 - 42% in one year against 321 the next. That is a platform migration timestamp, not a founding date. Anything keyed on created_at will read a migration as a boom.
SECOND TRAP: sustainable_development_goals is a SET SERVED IN ARBITRARY ORDER. Refetching page 1 hours after the baseline, all 25 rows carried an identical set of goals and 24 of the 25 came back in a different order - Goal 8 first became Goal 4 first. A derived "primary SDG" taken from the first element is noise. Sort the list before comparing or reporting.
THAT ALSO MEANS DEDUPE WILL NEVER FIRE HERE. Same length, same ids in the same order, different bytes, on every fetch. It is not the same mechanism as wss-gho's (which is object key order and a regenerated surrogate, and is fixed by dedupe_canon: json - sorting object keys does not reorder a list). Fixing this one needs canonicalisation that sorts nested arrays, and the engine is deliberately not growing that for ~2-3 MB a month: a full copy of 169 pages every month is the accepted cost here, and it is written down rather than discovered later.

## Reusing this data

The captures in this repository are bytes as the publisher served them. Each
source's own licence or terms of service govern reuse — they are listed per
source above and they are not all the same. This repository's code is separate
from the data it collects; check the source before redistributing.
